# GRC Risk Assessment — PayNova Microfinance

> Controlled mentorship scenario involving a fictional microfinance institution.

## Objective

Build a structured cybersecurity risk register by identifying risks, connecting threats to vulnerabilities and affected assets, assigning likelihood and impact scores, documenting existing controls, and selecting appropriate treatment actions.

## Risk Assessment Method

The exercise used a **5×5 likelihood and impact model**:

`Raw Risk Score = Likelihood × Impact`

The workbook defined the following bands:

- **Low:** 1–6
- **Medium:** 8–12
- **High:** 15–20
- **Critical:** 25

Treatment options included **Avoid, Mitigate, Transfer, and Accept**.

## Risks Assessed

My completed register included scenarios covering areas such as:

- insecure API exposure in a mobile banking application;
- third-party/vendor security risk;
- cloud-service availability;
- phishing and credential compromise; and
- ransomware affecting critical systems.

For each risk, the register documented the affected asset, threat source, vulnerability, likelihood, impact, existing controls, treatment decision, treatment actions, owner, target date, and status.

## Example — Insecure API Risk

The mobile-application API scenario was assessed against weak access controls and insufficient API security testing. The documented treatment focused on penetration testing, periodic API-permission review, and security approval of new endpoints before deployment.

## Key Learning

The exercise reinforced that risk scoring is not simply assigning numbers. Scores need to be anchored to business consequences and supported by a defensible rationale. Treatment decisions also need ownership, actions and review dates to become operational rather than remaining theoretical risks.

## What This Lab Demonstrates

- Cybersecurity risk identification
- Asset/threat/vulnerability relationships
- Likelihood and impact scoring
- Risk treatment planning
- Control-gap analysis
- Risk ownership and target dates
- Business-focused security documentation
